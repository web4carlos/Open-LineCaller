# CP-0036.2.4.3 — Persistent Wizard Session Restore

Purpose: server restarts must not force court recalibration or ball reselection.

## Persisted Wizard artifacts

The existing runtime folder keeps:

- `EXTERNAL_GRID_CALIBRATION.json`
- `EXTERNAL_GRID_BACKGROUND.png`
- `BALL_TEMPLATE.png`
- `WIZARD_SESSION.json` (new)

The new manifest stores only the runtime ownership needed to reconstruct the
official outside-only live runtime: camera id, mount, owned outside zones,
receiving side, and outside depth.

## Restore behavior

- Legacy sessions with court/background/ball are detected and offered through
  **Resume Previous Calibration**.
- The first resume creates `WIZARD_SESSION.json`.
- Later server boots automatically rebuild the runtime from the saved manifest.
- After a browser refresh, the operator still uploads/selects the local video
  file because browsers do not retain local file bytes across reloads. Loading
  that video no longer clears the restored runtime.
- Video dimensions must match the saved calibration.
- **Reset Calibration** explicitly clears the persisted Wizard artifacts so a
  deliberately reset court is not resurrected on the next boot.

## Safety contract

This pack changes persistence and Wizard state only. It does not change ball
detection, contact recovery, Z0, UP confirmation, line-touch rules, camera
ownership, camera pose safety, or the OUTSIDE GRID ONLY architecture.
