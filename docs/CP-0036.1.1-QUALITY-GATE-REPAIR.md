# CP-0036.1.1 - Quality Gate Repair

Status: REPAIR PACK

## Why this repair exists

The CP-0036.1 installer used `$ErrorActionPreference = "Stop"` but did not
explicitly inspect `$LASTEXITCODE` after native commands such as `python`,
`pytest`, `git`, and `pip`.

Windows PowerShell therefore continued after a failing `pytest` process and
eventually committed/pushed CP-0036.1 even though its quality gate had failed.

CP-0036.1.1 makes native exit-code checking explicit.

## Repairs

### Immediate OUT glow

A new glow was created with:

`started_at_s == current now_s`

The previous fade-in formula therefore evaluated to zero on the exact OUT
confirmation frame.

The repaired envelope starts with a visible 35% fade-in level and ramps to full
strength while retaining the existing fade-out.

### PySide6 dependency

The complete repository contains historical desktop/product-shell tests that
import PySide6.

`requirements.txt` now includes `PySide6>=6.7` so the documented full-suite
quality gate has all repo-level test dependencies.

### Generated runtime state

`.linecaller_runtime/` is generated by the browser wizard and tests.

It is now ignored by Git and remains local runtime state.

### Strict PowerShell quality gate

`tools/run_quality_gate.ps1` exits immediately when the full pytest suite or
`git diff --check` returns a non-zero native exit code.

Future capability-pack installers must use the same explicit
`$LASTEXITCODE` pattern before commit/push.

## Release rule

CP-0036.1.1 is not considered successful unless the local machine prints:

`QUALITY GATE PASSED`

and the repair installer then commits and pushes.
