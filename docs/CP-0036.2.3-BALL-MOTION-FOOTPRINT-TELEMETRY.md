# CP-0036.2.3 - Ball Motion Footprint + Live Event Telemetry

Status: IMPLEMENTED

The first real 60 FPS video showed that a fast pickleball can appear as a
compact ball core plus a same-color halo/streak near floor impact.

The runtime still begins with Pillow `ImageChops.difference()` against the
calibration-owned background, followed by the locked ball-color mask.

OpenCV produces raw color components. Nearby plausible fragments can now be
merged into one Ball Motion Footprint. The footprint preserves the compact
core scale so the halo does not make the ball appear artificially larger.

Before Z0, the candidate image point is projected onto the calibrated court
floor in Ball Units. Its distance from the legal court rectangle is measured.
If the external clearance is below the conservative
`min_outside_clearance_bu` guard, that observation cannot become OUT evidence.

Default guard: `0.20 BU`.

This is an uncertainty guard, not a claim about the exact physical size of the
ball's contact patch. The safety invariant is:

`touch / uncertain boundary -> NO OUT evidence`

The same floor geometry reads `ExternalGridCalibration.coverage`; therefore
FULL_COURT and HALF_COURT use the same guard implementation.

The live API now exposes ball pixels, raw blobs, merged footprints, blur
merges, line-guard rejections, detailed Z0 events and detailed UP events.

The Wizard accumulates Z0, UP, OUT and line-guard totals and keeps a rolling
video-frame event log.

`POST /api/live/reset-events` clears Z0/UP/cooldown/glow state before each
analysis run without changing court calibration, ball identity, ownership or
receiving side. This makes replaying the same video segment deterministic.

No interior scan was introduced. The operational path remains:

frame -> Pose Guard -> owned external cells -> Pillow/color
-> Ball Motion Footprint -> line-touch guard -> Z0 -> UP -> OUT -> glow
