# CP-0035.9.4.2 RC4 — Flight-Epoch Direction Change

Baseline: secured CP-0035.9.4.1 plus installed/uncommitted RC3 Ball-Unit + Time Paths.

This RC adds the missing runtime concept between continuous paths:

`OLD PATH -> meaningful above-floor direction change -> NEW FLIGHT EPOCH`

The detector consumes only timed continuous positions `P(x,y,z,t)`. Ball appearance
remains WHO-only and is not an input to the trajectory equations.

The detector compares a short incoming ballistic fit with a short outgoing fit,
compensating for gravity before comparing velocity. A smooth ballistic arc must not
create a new epoch. A floor bounce is classified separately from an above-floor
change so bounce and paddle-return semantics are not merged.

The real video gate intentionally may use explicit same-ball reacquisition only to
obtain post-change observations for engineering validation. That is not a production
search policy and does not alter secured CP-0035.9.4.1.

No glow changes. No commit/tag.
