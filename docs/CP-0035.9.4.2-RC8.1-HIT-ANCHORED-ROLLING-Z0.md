# CP-0035.9.4.2 RC8.1 — Hit-Anchored Rolling Three-Point Z0

## Correction

RC8 attempted to solve more continuous XYZ geometry than this flight-loop needs at this stage. RC8.1 returns to the agreed flight logic.

## Contract

1. A direction-changing paddle impact starts a new flight epoch.
2. The trusted impact observation is `H0=(x0,y0,z0,t0)`.
3. Two post-impact observations produce the first window: `H0,P1,P2`.
4. Each later observation shifts by one point: `P1,P2,P3`, then `P2,P3,P4`, etc.
5. Each three-point window predicts only the next `Z=0` intersection.
6. No complete path is calculated or stored.
7. A later paddle impact discards the old rolling window and starts a new one.
8. Same-ball continuity is preserved locally; global reacquisition remains forbidden during the transition.

## Separation of concerns

- Ball Identity = WHO.
- Same-ball observations + timestamps = motion evidence.
- Three-point window = current Z0 estimate.
- Cells/mesh may discretize observations but do not mathematically define the curve.
- RC8 continuous XYZ is not used by the RC8.1 sequencing gate.

## Gate purpose

The real-video gate validates the sequence `HIT -> H0,P1,P2 -> P1,P2,P3 -> ...`. It does not yet claim final Z0 accuracy from the engineering observation adapter.
