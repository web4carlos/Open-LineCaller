# CP-0035.9.4.2 RC6 — Rolling Three-Point Z0 Predictor

## Locked concept

LineCaller does **not** need to calculate or retain an entire flight path.
During one uninterrupted flight it keeps only the latest three trusted timed
positions:

- `P1=(x1,y1,z1,t1)`
- `P2=(x2,y2,z2,t2)`
- `P3=(x3,y3,z3,t3)`

From those three observations RC6 estimates the **current** local velocity and
projects only far enough to estimate the next intersection with the Contact
Plane `Z=0`.

When `P4` arrives, `P1` is discarded and the window becomes `P2,P3,P4`.
Therefore the Z0 estimate is recomputed continuously as the ball moves.

## Separation of responsibilities

- Ball Identity answers **WHO**.
- `P(x,y,z,t)` answers **WHERE / WHEN**.
- The latest three timed points estimate **current motion**.
- RC6 predicts **where that local motion reaches Z=0**.
- DCF cells may discretize observations, but they do **not** define the Z0
  mathematics.
- No complete `FlightPath` object is needed by the RC6 core predictor.

## Direction changes

A paddle hit / meaningful direction change ends the previous rolling window.
The BallSession continues via RC5 local transition continuity.  Three new
trusted points seed a new RC6 rolling window.

## Real gate status

The included real-video gate is deliberately diagnostic.  It prints each
rolling Z0 estimate and shows the tracked ball plus the current predicted floor
point in an engineering-only video.  It does **not** declare convergence or a
real bounce until the observed continuous XYZ values themselves are validated.

Production DCF/mesh/path overlays remain invisible.
