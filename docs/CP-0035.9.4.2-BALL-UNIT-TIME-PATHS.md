# CP-0035.9.4.2 RC3 — Ball-Unit + Time Continuous Flight Paths

Baseline: secured CP-0035.9.4.1 (`fdef013`).

## Locked conceptual contract

The ball image/profile answers **WHO**. It does not define a curve.

A tern `P=(x,y,z)` is exactly one mathematical point in 3D court space.
A flight is a continuous curve `P(t)`.

The primary spatial unit is one **Ball Unit (BU)**, approximately one ball
diameter. The current locked X scale is:

- 20 ft / 83 = 2.891566 in per BU.
- court X range = 0..83.0 BU.
- using that same BU continuously, court Y range = 0..182.6 BU.
- `Z=0` = Contact Plane.
- `Z=1` = one Ball Unit above the Contact Plane.
- Z increases upward.

The existing 83x182 DCF remains a discrete approximation/indexing layer. It
does **not** define the continuous flight curve.

## Time is mandatory

A path state is not only `P=(x,y,z)`. Every observation has a real timestamp:

`O_i = (P_i, t_i)`

Velocity is therefore measured from displacement over elapsed time:

`V=(vx,vy,vz)` in BU/s.

For the initial ballistic baseline, gravity is converted once into the same
coordinate scale: about 133.522 BU/s² for the current Ball Unit.

A direction change / paddle hit starts a new flight epoch with:

`P0 + V0 + t0 -> P(t) -> predicted contact time -> predicted Z=0`

Every return creates a new `P0`, `V0`, `t0` and therefore a new path.

## One P0, many possible Z0

From one P0 the opposite `Z=0` plane contains many possible receiving points.
Those are possible path endpoints. The outgoing velocity and time state select
the active predicted path; later observations will verify/correct it.

The path is a curve, not a tube and not a chain of cells. A tolerance envelope
may be added later for measurement uncertainty, but it is not the physical path.

## Pre-serve bounce

A floor touch before the paddle strike does not itself create the outbound serve
flight epoch. The paddle-driven direction change provides the new `P0 + V0 + t0`.
