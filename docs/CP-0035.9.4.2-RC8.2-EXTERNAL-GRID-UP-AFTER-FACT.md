# CP-0035.9.4.2 RC8.2 — External Grid + Calibrated Reference + UP After-the-Fact

## Locked architecture

### Court Calibration owns the grid

1. Build the external grid in 2D top view.
2. Project that fixed grid into camera perspective.
3. Store the external cells, local floor ball scale and image-UP direction.
4. Save the background/reference used by Pillow.

Runtime never builds or moves the grid.

### Game runtime order

`FRAME -> PILLOW (current cell vs calibrated reference cell) -> EXTERNAL CELL LOOP -> OUR BALL AT Z0 CANDIDATE -> UP AFTER THE FACT -> BINGO`

A Z0 candidate by itself is **not** a bounce and is **not** an OUT call.

After a Z0 candidate, only one post-event condition is required:

- the same locked-ball color/residual appears **ABOVE** the contact location by approximately one Ball Unit, within a short after-the-fact window.

There is deliberately:

- no DOWN prerequisite;
- no flight-path calculation;
- no XYZ resolver;
- no velocity requirement;
- no global ball tracker;
- no moving cell.

The grid is engineering-visible only. Production keeps it invisible.

## BINGO contract

`OUR BALL @ external Z0 candidate` + `SAME BALL ABOVE after the fact` = `BINGO candidate for OUT`.

This RC is an engineering gate. It does not enable the official Game OUT decision yet.

## Perspective correction

The External Grid is calibration-owned. It is first a regular 2D floor lattice in court coordinates. LineCaller court convention is FAR `Y=0` and NEAR `Y=max`. Each of the four corners of every external cell is then projected through the calibrated floor homography. Runtime must consume these projected quadrilaterals; image-axis-aligned rectangles are not the grid geometry.
