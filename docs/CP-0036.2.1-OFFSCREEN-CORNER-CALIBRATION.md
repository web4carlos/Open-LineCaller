# CP-0036.2.1 - Off-Screen Corner Calibration

Status: IMPLEMENTED

## Problem found by the first real video

A fixed pickleball camera may clearly see portions of all four OUTER court
boundary lines while one or more mathematical court corners lie outside the
image.

Requiring every corner to be clickable would force a false edge-point guess or
reject an otherwise useful camera view.

## Boundary Lines mode

The Video-First Wizard now defaults to `Boundary Lines`.

The operator clicks two visible points on each OUTER boundary:

1. NEAR baseline;
2. RIGHT sideline;
3. FAR baseline;
4. LEFT sideline.

All eight evidence clicks must be on-screen.

LineCaller extends the four image lines mathematically and computes:

- near-left = NEAR x LEFT;
- near-right = NEAR x RIGHT;
- far-right = FAR x RIGHT;
- far-left = FAR x LEFT.

An inferred corner may lie outside the image.

## Safety checks

The inference rejects malformed evidence, off-screen clicks, extremely short
segments, nearly parallel adjacent boundaries, non-finite intersections,
implausibly distant inferred corners, self-crossing quadrilaterals and
degenerate homographies.

## External Grid behavior

No second grid implementation is introduced.

The inferred corners are passed to the existing `ExternalGridCalibrator`,
which continues to create only outside-court floor cells and retain only
projected cells with visible image bboxes.

`4 Visible Corners` remains available as a compatibility mode.

Video transport labels use ASCII `Step Back` / `Step Forward` to avoid encoding
artifacts.
## API compatibility

The public `/health` contract remains:

`version = CP-0036.2`

The off-screen-corner feature reports separately:

`feature_version = CP-0036.2.1`

Video transport controls retain the historical phrase `Step Frame` and use
ASCII-only labels:

- `Step Frame Back`
- `Step Frame Forward`
