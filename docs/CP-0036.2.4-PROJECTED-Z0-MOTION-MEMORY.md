# CP-0036.2.4 — Projected Z0 Ball Signatures + Short Motion Memory

## Why

Real-video telemetry from the FAR_LEFT reference OUT exposed a failure mode in
CP-0036.2.3: a persistent ball-colored object could repeatedly satisfy the
color + floor-scale gate and flood Z0/UP/OUT telemetry.

CP-0036.2.4 adds two fail-closed gates to the Wizard/API live runtime while
preserving the historical low-level ExternalGridFrameLoop defaults.

## Five projected Z0 ball signatures per exterior cell

Every active exterior cell precomputes five physical floor-contact hypotheses:
CENTER, NORTH, SOUTH, EAST and WEST.

Each hypothesis stores its projected image center and the local diameter that
one pickleball (1 Ball Unit) should have at Z=0 from the calibrated camera.

The selected-ball template still provides the locked hue profile and now also
provides a tight foreground fill-ratio cue. A fast core+halo footprint is still
allowed; appearance is supportive, not a brittle hard texture match.

## Short motion memory

Before a projected Z0 candidate is admitted, the live Wizard/API runtime checks
the previous three frame windows for a compatible moving observation chain.

The gate rejects stationary/persistent ball-colored objects, candidates that
appear at Z0 with no plausible prior motion, and candidates whose short linear
prediction misses the current projected Z0 hypothesis by too much.

This memory is image-space evidence only. It does not create or traverse an
interior court grid.

## Safety invariant

Prediction can focus or reject evidence, but prediction alone can never call
OUT.

The official decision remains:

selected-ball evidence
→ short approach evidence
→ exterior projected Z0 match
→ line-touch guard
→ Z0
→ UP after fact
→ confirmed OUT

The operational line-call grid remains EXTERIOR ONLY.

## Compatibility

Historical health keys remain unchanged:

- `version = CP-0036.2`
- `feature_version = CP-0036.2.1`
- `runtime_feature_version = CP-0036.2.3`

A new additive key is exposed:

- `ball_identity_feature_version = CP-0036.2.4`

The strict projected/motion gate is enabled by the live API/Wizard registry.
Direct construction of `OfficialExternalLiveRuntime` keeps historical defaults
unless the new config flags are explicitly enabled.

## New telemetry

The Wizard/API exposes projected signature matches/rejections,
approach-memory rejections, motion-history observation count and predicted Z0
cell. These are diagnostic evidence only; they do not change pickleball line
rules.
