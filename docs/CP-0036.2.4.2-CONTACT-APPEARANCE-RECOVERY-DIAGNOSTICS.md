# CP-0036.2.4.2 — Contact Appearance Recovery + Approach Diagnostics

This pack addresses a real-video failure mode observed at the reference FAR_LEFT
bounce: the selected yellow pickleball can become bright/desaturated for one or
two frames at contact because of exposure, blur and compression.

## Safety contract

Contact recovery is not a second ball detector and it cannot create OUT by
itself. Recovery is allowed only when:

1. locked-color ball observations already form a short coherent image-space
   trajectory;
2. that trajectory is moving physically DOWN according to calibration-owned
   image-up;
3. its next predicted point is near one of the five projected Z0 signatures in
   an active external cell;
4. a small changed component exists in that predicted neighborhood with
   compatible floor scale and bright/desaturated or relaxed selected-ball
   appearance;
5. the recovered component still passes the normal external-cell geometry,
   projected signature, approach-memory, line-touch guard, and later UP
   confirmation.

Recovery is capped at two consecutive frames by default. The active runtime
calibration already contains only camera-owned cells on the receiving side, so
no interior operational grid is introduced.

## New telemetry

- CONTACT RECOVERIES / RECOVERY FRAME
- APPROACH REASON
- TOTAL MOTION PX / MIN MOTION PX
- PRED ERROR PX / ALLOWED ERROR PX
- CANDIDATE CELL
- PROJECTED ANCHOR

These diagnostics make approach rejection explicit instead of reporting only a
counter.
