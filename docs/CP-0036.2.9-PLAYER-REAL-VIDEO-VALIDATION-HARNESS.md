# CP-0036.2.9 — Player Real-Video Validation Harness

## Purpose

CP-0036.2.8 proves the complete Player chain on deterministic rendered RGB
frames. CP-0036.2.9 prepares the same official runtime for the first real
phone-on-net clip.

The harness is diagnostic-first. A run without human truth does **not** claim
accuracy. It reports `DIAGNOSTIC_COMPLETED`.

If explicit truth is supplied, it reports `TRUTH_PASS` or `TRUTH_FAIL`.

## One-command real clip validation

Example OUT clip:

```powershell
cd C:\olinecaller

.\.venv\Scripts\python.exe .\tools\validate_player_real_video.py `
  --video C:\video\player_clip.mp4 `
  --calibration C:\video\calibration_half_court.json `
  --background C:\video\background.png `
  --ball-template C:\video\ball_template.png `
  --mount-side RIGHT `
  --expect-out 147:OUT_LEFT
```

Example IN/no-OUT clip:

```powershell
.\.venv\Scripts\python.exe .\tools\validate_player_real_video.py `
  --video C:\video\player_in_clip.mp4 `
  --calibration C:\video\calibration_half_court.json `
  --background C:\video\background.png `
  --ball-template C:\video\ball_template.png `
  --mount-side RIGHT `
  --expect-no-out
```

Without either truth option, the same command still produces all diagnostics
but deliberately makes no accuracy claim.

## Output

Default directory:

```text
.linecaller_runtime/validation/<video-name>/
```

Artifacts:

```text
report.json
timeline.jsonl
timeline.csv
keyframes/
```

The timeline captures, per original video frame:

- pose state and reason;
- scan suppression;
- selected-ball component counts;
- trajectory lock state and depth;
- Net-Ingress reason/start/end/inward delta;
- Z0 candidates and regions;
- UP confirmations and their contact frames;
- official OUT calls;
- scale diagnostic reason;
- approach diagnostic reason.

Keyframe PNG files are produced only on significant event frames: pose not
SAFE, BOOTSTRAP, accepted Net-Ingress, Z0, UP, or official OUT.

No output video codec is required.

## Safety / calibration rules

Player validation requires `HALF_COURT`.

The decoded real video must have the **exact same image size** as calibration.
The harness refuses to resize or rotate frames automatically because doing so
would silently invalidate the court homography and external cell geometry.

The runtime remains:

```text
REAL RGB FRAME
 -> pose guard
 -> selected-ball image components
 -> Player Net-Ingress
 -> trajectory identity / Top-3
 -> projected Z0
 -> UP after the fact
 -> immutable OUTSIDE external cells
 -> official OUT
```

No interior decision grid is introduced.

## Truth options

`--expect-out FRAME:REGION` may be repeated. The default contact-frame
tolerance is +/-2 frames and can be changed with `--contact-tolerance`.

`--expect-no-out` asserts zero official OUT calls in the selected frame range.

`--expect-out` and `--expect-no-out` are mutually exclusive.

## Frame ranges

A long recording can be restricted without altering original frame numbers:

```text
--start-frame 1200 --end-frame 1500
```

## Important limitation

This pack prepares the real-video diagnostic/validation machinery. It does not
manufacture physical validation.

The first genuine phone-on-net clip is still required to test motion blur,
auto exposure, rolling shutter, compression, glare/shadows, real apparent ball
size, and real camera vibration. Those effects must be measured, not guessed.
