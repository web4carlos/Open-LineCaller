# CP-0035.9.4.2 RC7 — Cell Residual Ball Verifier

## Purpose

Validate the user's proposed observation rule before feeding points into the rolling three-point Z0 predictor:

`CURRENT aligned cell image - BACKGROUND aligned cell image -> foreground residual`

The subtraction is implemented with Pillow/PIL `ImageChops.difference()`.

## Responsibility boundary

- Ball Identity / appearance answers **WHO** and stays in `BallInMeshSearcher`.
- Cell Residual answers only **did foreground appear where the identified ball is expected?**
- Residual evidence does **not** define XYZ.
- Residual evidence does **not** define the flight curve.
- Rolling 3-point Z0 remains downstream and unchanged.

## Runtime background

Production must maintain/learn a background image for a cell/ROI only while that region is known to be empty. The engineering gate uses an explicitly supplied earlier frame as a test background. That frame number is never production logic.

## Safety / invariants

- CP-0035.9.4.1 tracked core remains unchanged.
- RC3/RC4/RC5/RC6 remain installed and unchanged.
- No global reacquisition during the RC5 direction-transition bridge.
- No YOLO/model added.
- Pillow is a Python image-processing dependency only.
